# Reproducibility record

This pack contains a fixed, verified Pf8 snapshot plus the code needed to rebuild its Kilifi subset and example outputs.

## Records

| File | Purpose |
|---|---|
| `source_manifest.json` | Original source/download URLs, data hashes, bibliography metadata and included-paper provenance. |
| `data_validation.json` | Inclusion totals, marker counts, observed-year coverage and input data hashes. Regenerated by the analysis. |
| `run_validation.json` | Environment versions and the checks actually performed when preparing the pack. |
| `file_manifest.json` | SHA-256 hashes and byte sizes of the delivered files, excluding this manifest itself and temporary Python caches. |
| `check_integrity.py` | Standard-library script checking each file listed in the file manifest. |

## What was checked

- The three bundled provider files matched fresh bytes downloaded from their official linked locations.
- Sample IDs were unique in each source table before the one-to-one join.
- Kenya/Kilifi and source QC/year selection produced the recorded inclusion counts.
- Retained recorded case-group keys were nonempty and unique.
- Mixed-call order was normalized consistently, and mixed calls were excluded from the secondary denominator.
- Years without samples retained missing prevalence and confidence limits.
- The ordinary Python notebook cells ran sequentially in the recorded local environment; the interactive Colab upload step was not exercised in a Google account.
- Example PNGs were visually inspected. Included PDFs were checked as readable PDF files with matching titles and attribution notices.
- The final ZIP was checked for archive integrity and a single top-level folder.

These checks support faithful reproduction of this snapshot. They cannot establish that all biological confounding or unrecorded repeated sampling has been resolved.

## Check an untouched extracted copy

From the project root, run:

```sh
python 07_Reproducibility/check_integrity.py
```

On Windows you can also use `py 07_Reproducibility\check_integrity.py`. This check needs only Python's standard library. It checks known delivered files; additional files are allowed and are not validated by this manifest.

Changes to a document or regenerated figure can legitimately produce a different hash. Keep an untouched downloaded copy as the comparison baseline, and record intentional revisions. Do not change the manifest merely to hide an unexplained difference.

## Reproduce the analysis

Follow `03_Analysis/HOW_TO_RUN.md`. The data/analysis dependencies are listed in `03_Analysis/requirements.txt`. The analysis reads original data from `02_Datasets/Original_Pf8`, writes derived data to `02_Datasets/Kilifi_Subsets`, and writes example results to `04_Example_Outputs`.

The analysis intentionally verifies known source hashes and snapshot totals. If the group uses another release or changes the scope, review the expected values and inclusion rules explicitly and record the revision before updating the validation code.
